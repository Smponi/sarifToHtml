Template authoring

Writing a custom report template

Templates are standard Go html/template files. Pass a single file for a compact template or a directory when you want reusable partials. If no template is provided, sarif-html uses the embedded default report.

Run with a Template

sarif-html reports/*.sarif \
  --template .github/sarif-html/report.tmpl \
  --out report.html

When --template points to a directory, sarif-html recursively loads files ending in .tmpl, .gotmpl, or .html in lexical order.

Validate and Inspect

Use --dry-run while developing a template. It loads SARIF, hydrates snippets, parses the template, and executes it against sarif-html.template.v1 without writing the HTML report or applying --fail-on.

sarif-html reports/*.sarif \
  --template .github/sarif-html/report.tmpl \
  --dry-run

Use --template-data-out to write the exact JSON object that the template receives. JSON uses lower-camel-case names such as schemaVersion and report.findings; Go templates use exported field names such as .SchemaVersion and .Report.Findings.

sarif-html reports/*.sarif \
  --template-data-out template-data.json \
  --dry-run

JSON Names vs Template Names

The naming difference is intentional. Use JSON to inspect values and structure, but use Go template field names when writing template expressions.

JSON contract fieldGo template field
schemaVersion.SchemaVersion
generatedAt.GeneratedAt
report.summary.total.Report.Summary.Total
report.summary.byBaselineState.Report.Summary.ByBaselineState
report.findings.Report.Findings
report.findings[].ruleID.RuleID inside range .Report.Findings
report.findings[].isBaseline.IsBaseline inside range .Report.Findings
report.findings[].sourceLink.SourceLink inside range .Report.Findings
baseline.hideUnchangedByDefault.Baseline.HideUnchangedByDefault

Minimal Template

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{ .Title }}</title>
</head>
<body>
  <h1>{{ .Title }}</h1>
  <p>{{ .Report.Summary.Total }} findings generated at {{ .GeneratedAt }}</p>
  <ul>
    {{ range .Report.Findings }}
      <li>
        <strong>{{ .Level }}</strong>
        {{ .RuleID }} in {{ .Path }}:{{ line .StartLine }}
      </li>
    {{ end }}
  </ul>
</body>
</html>

Modular Template Directory

A directory template can split the main document and reusable partials into separate files.

{{ define "finding-row" }}
<tr>
  <td>{{ .ID }}</td>
  <td>{{ .Level }}</td>
  <td>{{ .RuleID }}</td>
  <td>
    {{ if .SourceLink }}
      <a href="{{ .SourceLink }}">{{ .Path }}:{{ line .StartLine }}</a>
    {{ else }}
      {{ .Path }}:{{ line .StartLine }}
    {{ end }}
  </td>
  <td>{{ .Message }}</td>
</tr>
{{ end }}
<!doctype html>
<html lang="en">
<body>
  <h1>{{ .Title }}</h1>
  <table>
    {{ range .Report.Findings }}
      {{ template "finding-row" . }}
    {{ end }}
  </table>
</body>
</html>

TemplateData v1

The current data contract is identified by sarif-html.template.v1. Use {{ .SchemaVersion }} in diagnostics or generated metadata when a template needs to assert the expected contract.

Baseline-aware templates can use .Baseline.HideUnchangedByDefault for the default visibility decision and .IsBaseline on each finding when rendering toggles or badges.

FieldDescription
.SchemaVersionTemplate data contract identifier. Currently sarif-html.template.v1.
.TitleEffective report title after CLI and report defaults are applied.
.GeneratedAtUTC render timestamp in RFC3339 format.
.ReportNormalized report data with Title, Sources, Findings, and Summary.
.SeveritiesOrdered severity counts, with common severities first.
.SourcesOrdered SARIF source counts derived from findings.
.ToolGroupsFindings grouped by tool name, densest groups first.
.RulesOrdered rule counts.
.FilesOrdered file counts.
.BaselineBaseline options and counts, including Enabled, HideUnchangedByDefault, New, Unchanged, ByState, and States.

Helpers

HelperDescription
severityClass <level>Maps a normalized severity to the CSS class used by the default template.
line <number>Renders missing line numbers as -.
sourceLink <finding>Builds a source URL for a finding using the same link options as the default template.
hasDetails <finding>Reports whether a finding has rule details, snippets, related locations, or code flows.
Security model

SARIF data is untrusted input and is escaped by Go html/template. A custom template is trusted input: do not run templates from untrusted sources, because template authors can intentionally add arbitrary HTML, JavaScript, external assets, or links to the generated report.

Compatibility

Compatible additions can extend sarif-html.template.v1. Breaking changes should introduce a new schema version so existing templates continue to have a clear contract.
